# Contributing

Thank you for contributing to an Aesir Enterprises repository.

## Before starting

- Confirm the repository’s README says the proposed work belongs there.
- Use the repository’s authoritative documentation and standards.
- Open an issue first when scope, ownership, or expected behavior is unclear.
- Never commit credentials, secrets, private customer data, payment data, or confidential exports.

## Branches

Use a short lowercase kebab-case description:

- `feat/<description>`
- `fix/<description>`
- `docs/<description>`
- `chore/<description>`
- `refactor/<description>`
- `agent/<description>` for approved AI-created branches

## Commits

Preferred format:

```text
type(scope): imperative description
```

Examples:

- `docs(site): update verified baseline`
- `fix(api): handle expired token`
- `feat(reporting): add monthly summary`

## Pull requests

Explain:

- What changed
- Why it changed
- Impact
- Validation performed
- Risks and rollback, when applicable
- Information still requiring confirmation

Keep unrelated changes out of the same pull request. AI-authored work should open as a draft for human review.

## Review

Material standards, production, infrastructure, security, legal, financial, HR, compliance, and public-facing changes require appropriate human review.
